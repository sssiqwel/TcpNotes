# TCP Notes Demo — учебный проект C#/.NET

Минимальный проект из двух консольных программ без ASP.NET и веб-фреймворков. Сервер хранит заметки только в оперативной памяти: после его перезапуска список очищается.

## Простой протокол обмена

Клиент и сервер обмениваются строками UTF-8; каждая команда и каждый ответ заканчиваются переводом строки. Клиент отправляет `ADD <текст>` для добавления заметки или `LIST` для получения списка. Сервер отвечает одной строкой: `OK ...`, `NOTES ...` или `ERROR ...`. Команда `EXIT` существует только в клиенте — она закрывает его, не отправляясь на сервер.

## Структура

```
TcpNotesDemo/
├── NotesServer/     # консольный TCP-сервер
└── NotesClient/     # консольный TCP-клиент
```

## Как запустить

Нужен .NET SDK 8 или новее. Откройте **три** терминала в папке `TcpNotesDemo`.

В первом запустите сервер:

```bash
dotnet run --project NotesServer
```

Во втором — первого клиента:

```bash
dotnet run --project NotesClient
```

В третьем — второго клиента:

```bash
dotnet run --project NotesClient
```

Пример демонстрации:

```
# Клиент 1
> ADD Купить хлеб
OK Заметка добавлена. Всего заметок: 1.

# Клиент 2
> ADD Подготовиться к защите
OK Заметка добавлена. Всего заметок: 2.

# Любой клиент
> LIST
NOTES 1. Купить хлеб | 2. Подготовиться к защите
```

Для выхода из клиента введите `EXIT`. Сервер останавливается сочетанием `Ctrl+C`.

## Как это работает

### Сервер

1. `TcpListener(IPAddress.Loopback, 5000)` создаёт точку ожидания соединений на этом компьютере. `Loopback` означает адрес `127.0.0.1`: подключиться можно только локально, что удобно и безопаснее для демонстрации.
2. `listener.Start()` начинает слушать порт. `AcceptTcpClientAsync()` ожидает следующего клиента и возвращает отдельный `TcpClient` для общения именно с ним.
3. После подключения запускается `Task.Run(() => HandleClientAsync(client))`. Основной цикл не ждёт этого клиента и сразу снова ждёт следующего — поэтому два клиента могут работать одновременно.
4. `NetworkStream` — поток байтов TCP. `StreamReader` и `StreamWriter` превращают его в удобный обмен строками UTF-8. `AutoFlush = true` отправляет строку сразу, а не оставляет её в буфере.
5. `ReadLineAsync()` ждёт команду. `ProcessCommand` распознаёт `ADD` и `LIST`, формирует ответ, а `WriteLineAsync()` отправляет его клиенту.
6. Список `notes` общий для всех обработчиков клиентов. `lock (notesLock)` не даёт двум потокам одновременно менять или читать этот список так, чтобы получился некорректный результат.
7. Блоки `using` гарантированно закрывают поток и сокет. `IOException` обрабатывает обычное отключение клиента; остальные ошибки выводятся на экран сервера.

### Клиент

1. `TcpClient` создаёт клиентский TCP-сокет, а `ConnectAsync(host, port)` подключает его к адресу и порту сервера.
2. Клиент получает `NetworkStream` и так же создаёт `StreamReader`/`StreamWriter`: у обеих сторон одинаковый строковый протокол.
3. В цикле `Console.ReadLine()` читает команду пользователя. `EXIT` не идёт в сеть: программа выходит из цикла и корректно закрывает соединение.
4. Для остальных команд `WriteLineAsync()` отправляет строку серверу, после чего `ReadLineAsync()` ожидает его одну строку-ответ. Затем ответ печатается в консоль.
5. Если сервер закрыл соединение, `ReadLineAsync()` вернёт `null`; если соединение оборвалось с ошибкой, сработает `IOException`. Если сервер недоступен в момент подключения, обычно возникает `SocketException`.

## Что показать и сказать на защите

1. Запустите сервер и два экземпляра клиента. На экране сервера должны появиться два подключения.
2. В первом клиенте добавьте заметку, во втором — ещё одну. Это доказывает, что оба клиента используют одно общее хранилище на сервере.
3. Выполните `LIST` в любом клиенте и покажите обе заметки.
4. Введите неизвестную команду, например `DELETE`, и покажите понятный `ERROR`.
5. Объясните цепочку: консоль клиента → `TcpClient` → TCP-соединение → `TcpListener` → обработчик клиента → список заметок → ответ тем же соединением.
6. При желании остановите сервер, когда клиент ожидает ответ, и покажите сообщение о закрытии/разрыве соединения. Реальная реакция ОС может немного отличаться: клиент либо быстро увидит закрытие, либо получит ошибку чтения.

## Готовые ответы на вопросы

### Чем client-server отличается от peer-to-peer?

В архитектуре клиент–сервер есть выделенный сервер: он хранит данные и оказывает услуги, а клиенты обращаются к нему. В peer-to-peer (P2P) равноправные участники могут одновременно быть и клиентами, и серверами, напрямую обмениваться данными друг с другом. В этом проекте сервер — центральный владелец списка заметок, поэтому это client-server.

### Что будет, если сервер выключить, пока клиент ждёт ответ?

TCP-соединение закроется или оборвётся. Ожидание чтения завершится: клиент увидит конец потока (`null`) либо сетевую ошибку (`IOException`/`SocketException`). В данном клиенте эти случаи не приводят к аварийному завершению: выводится сообщение, а программа завершает работу. В реальном приложении можно предложить повторное подключение.

### Зачем нужен порт, если есть IP-адрес?

IP-адрес указывает компьютер или сетевой интерфейс, а порт — конкретную программу (службу) на нём. Один компьютер с IP `127.0.0.1` может одновременно иметь сервер заметок на порту 5000, другой сервис на 5001 и т. д. Поэтому адрес TCP-соединения — это пара «IP + порт».

### ASP.NET-проект и «сырой» TCP-сервер — оба ли client-server? В чём разница?

Да, оба являются клиент–серверными: клиент посылает запрос, сервер отвечает. ASP.NET обычно принимает HTTP-запросы и предоставляет много готовой инфраструктуры: маршрутизацию, обработку HTTP, сериализацию, middleware, аутентификацию и другие механизмы. Здесь используется только TCP: мы сами придумали текстовый протокол, вручную читаем и пишем строки, сами определяем команды и сами отвечаем за обработку ошибок. TCP — уровень ниже HTTP.

### Какие типичные угрозы безопасности есть в ASP.NET-проекте?

* Недостаточная аутентификация и авторизация: пользователь получает доступ к чужим данным или к административным действиям.
* Инъекции, например SQL injection, если строить запросы строковой склейкой вместо параметров/ORM.
* XSS: вывод пользовательского текста в HTML без правильного экранирования.
* CSRF: чужой сайт заставляет уже вошедшего пользователя выполнить нежелательное действие.
* Утечка секретов: пароли, ключи API или строки подключения попали в код, репозиторий, логи или сообщения об ошибках.
* Небезопасная обработка файлов: загрузка вредоносных или слишком больших файлов, чтение пути вне разрешённой папки.
* Отсутствие HTTPS, слабые настройки cookies/sessions и устаревшие зависимости.
* Отсутствие ограничений запросов: злоумышленник может создать много запросов и перегрузить приложение (DoS).

Для настоящего приложения также потребуются проверка длины команд, аутентификация, шифрование TLS и ограничение частоты запросов. В учебной локальной версии это специально не реализовано, чтобы код оставался минимальным.

## Работа в Visual Studio Code на Mac

1. Установите **.NET SDK 8+** с сайта https://dotnet.microsoft.com/download/dotnet/8.0.
2. Установите VS Code и откройте в нём папку `TcpNotesDemo` через **File → Open Folder**.
3. VS Code предложит установить рекомендованные расширения из `.vscode/extensions.json`: **C# Dev Kit** и **C#** от Microsoft. Согласитесь с установкой.
4. Откройте встроенный терминал (**Terminal → New Terminal**) и выполните команды запуска из раздела выше. Для двух клиентов понадобятся два терминала внутри VS Code (или два отдельных окна Terminal).
5. Файл `Ответы-на-вопросы.txt` содержит отдельные готовые ответы для подготовки к защите.
